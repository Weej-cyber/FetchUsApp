Overview

What This Is

FetchUs is a dog walking service management app built for a single business owner. It handles three user roles (Admin, Walker, Client) with role-based routing, walk booking and management, walker assignment, walk completion with notes and photos, and in-app notifications. SMS notifications are built but not yet wired to Twilio.

The project owner is Clarence Wheeler. All technical decisions go through him. Contact via Nancy (the business owner / Admin user).

Tech Stack

Architecture

Frontend

React with Vite. Tailwind CSS. Single-page application. No backend server -- all data calls go directly to Supabase from the client.

Database + Auth

Supabase (PostgreSQL). Handles all data storage, row-level security, and authentication. Magic link auth -- no passwords for end users.

Deployment

Vercel. Auto-deploys on every push to the main branch of the GitHub repo. No build configuration needed beyond what's already in vercel.json.

Version Control

GitHub. Repo: github.com/Weej-cyber/FetchUsApp. Single branch (main). No PR workflow -- direct pushes to main.

Auth Flow

How Authentication Works

FetchUs uses Supabase magic link auth. New user signup is disabled -- users can only be added by an admin via the Supabase dashboard (Authentication > Users > Invite user).

On first login, useAuth.jsx checks if the user has a row in public.users. If not, it creates one using the role stored in the user's auth metadata. This is how role-based routing works -- the app reads the role from public.users and sends the user to the correct screen.

Adding a new user: Supabase Dashboard > Authentication > Users > Invite user. Set their role metadata to admin, walker, or client. The app handles the rest on first login.
Do not touch these files without tracing the full auth flow first: useAuth.jsx, App.jsx, LoginPage.jsx, supabase.js. A change in one breaks the others.

Deployment

How to Deploy

Vercel is connected to the GitHub repo. Every push to main triggers an automatic deployment. There is no manual deploy step. If a build fails, Vercel keeps the last working version live.

# To deploy a change: 1. Push updated file(s) to main branch on GitHub 2. Vercel auto-builds (takes ~60-90 seconds) 3. Live app updates automatically # To check build status: vercel.com > FetchUs project > Deployments tab
UAT Automation

Running Automated Tests

A full automated test suite runs all 21 UAT test cases across all three roles using Playwright via Browserbase cloud browsers. Tests run automatically on every push to main.

# Test users (created in Supabase, not real emails): fetchusadmin@test.com -- role: admin fetchuswalker@test.com -- role: walker fetchusclient@test.com -- role: client password for all three: FetchTest1! # Auth method: password signin via /auth/v1/token?grant_type=password # Session injected into localStorage before page load # Tests run against live Vercel URL # To trigger manually: GitHub repo > Actions tab > FetchUs UAT > Run workflow
If tests fail with "Database error querying schema": The test users' confirmation_token field in auth.users has reverted to NULL. Fix with:

UPDATE auth.users SET confirmation_token='', recovery_token='', email_change_token_new='', email_change='' WHERE email LIKE 'fetchus%@test.com';

Known Issues

Watch Out For

Auth file fragility

useAuth.jsx, App.jsx, LoginPage.jsx, and supabase.js are tightly coupled. Changing one without tracing the full session flow has caused regressions before. Always read through the complete flow before touching any of these.

Demo Mode buttons

LoginPage.jsx still contains Demo Mode buttons from an earlier development phase. These should be removed before go-live.

Vercel build failures

Partial or broken file pushes have caused build failures. Always verify the complete file before pushing. Run npm run build locally if possible before pushing to main.

SMS trigger fires on every notification insert

The on_notification_insert trigger calls the send-sms Edge Function on every insert with status=pending. Until Twilio is wired, this call fails silently. Insert notifications with status=sent to avoid triggering it during development.
