Background

Why We Built This

UAT was delayed because human testers weren't moving fast enough. Rather than wait, we automated the entire test plan — all three roles, all 21 test cases — using Playwright running on GitHub Actions. No local development environment, no paid browser service, no manual steps required.

The tests run against the live Vercel deployment at fetchus.vercel.app and produce a pass/fail report per test case, committed back to the repo automatically after every run.

Auth Strategy

How Login Works Without Email

FetchUs uses magic link auth for real users. For automated testing, magic links require receiving email which isn't possible in a headless runner. The solution uses two steps.

First, test users were created directly in Supabase's auth.users table via SQL with a known password. Several fields that Supabase requires (confirmation_token, recovery_token, email_change fields) must be set to empty strings, not NULL, or password auth will throw a database error.

Second, the test script calls the standard password sign-in endpoint to get a session, then injects that session into the browser's localStorage before the app loads. The localStorage key the app uses is derived from the Supabase project URL by the supabase-js library: sb-rwauwkrdzcesyhwpaeow-auth-token.

// Auth flow in uat.js POST /auth/v1/token?grant_type=password { email: "fetchusadmin@test.com", password: "[stored in UAT_ADMIN_PASSWORD secret]" } → returns full session object including user // Session injected into browser localStorage before page load localStorage.setItem('sb-rwauwkrdzcesyhwpaeow-auth-token', JSON.stringify(session)) → page reloads → app reads session → routes to correct role screen
Key lesson learned: The supabase-js client library overrides the default auth-js storage key. The correct key is derived from the project hostname, not the auth-js package default of 'supabase.auth.token'. Always verify the actual key by reading the installed supabase-js source in node_modules before writing any session injection code.
Environment Verification

Pre-Flight Checks

The workflow runs three checks before any test code executes. If any fail, the job stops immediately and writes the failure reason to uat-results.txt.

1. App URL check

Confirms fetchus.vercel.app returns HTTP 200, 301, or 302. Catches dead deployments before wasting time running tests.

2. Supabase check

Confirms the Supabase REST endpoint is reachable and responding.

3. Test user auth check

Confirms the admin test account can sign in successfully. Catches any database issues with the test users before the full suite runs.

Files in Repo

What Runs the Tests

uat/uat.js

The full test script. Handles password auth, localStorage session injection, all 21 test cases across three roles, and writes uat-results.txt.

uat/package.json

Single dependency: playwright.

.github/workflows/uat.yml

GitHub Actions workflow. Triggers on every push to main. Runs environment checks first, installs Playwright Chromium, runs tests, commits uat-results.txt back to the repo.

uat-results.txt

Auto-committed after every run. Contains debug state (what URL loaded, what localStorage contained, what was on screen) followed by the full pass/fail report.

How to Run

Triggering a Test Run

Automatic (current setting)

  1. Any push to the main branch triggers the workflow automatically.
  2. Wait approximately 10 minutes for the run to complete.
  3. Pull the repo or check the Actions tab — uat-results.txt is updated with the latest results.
Manual trigger: GitHub repo > Actions tab > FetchUs UAT > Run workflow. No code push needed.
