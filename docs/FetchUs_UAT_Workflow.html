Background

Why We Built This

UAT was delayed because human testers weren't moving fast enough. Rather than wait, we automated the entire test plan — all three roles, all 21 test cases — using a cloud browser service (Browserbase) running Playwright scripts triggered from GitHub Actions. No local development environment required.

The tests run against the live Vercel deployment and produce a pass/fail report per test case.

Auth Strategy

How Login Works Without Email

FetchUs uses magic link auth — normally a user receives an email and clicks a link. For automation that doesn't work. The solution: use the Supabase service role key to call the generate_link admin API, which produces a valid session token directly. That token is injected into the browser's localStorage before the page loads, so the app sees a fully authenticated session.

POST /auth/v1/admin/generate_link { "type": "magiclink", "email": "fetchuswalker@test.com" } → returns access_token + refresh_token → injected into localStorage as sb-[project]-auth-token → page reloads as authenticated user

How to Run

Triggering a Test Run

Automatic (current setting)

  1. Any push to the main branch triggers the workflow automatically.
  2. Go to the Actions tab in the GitHub repo.
  3. Click the most recent "FetchUs UAT" run.
  4. Expand the "Run UAT" step to see full pass/fail results.
Re-running: The workflow can also be triggered manually from the Actions tab using the "Run workflow" button, without needing to push any code changes.
Known Limitations

What This Doesn't Cover

A-04 — Create booking (marked SKIP)

The booking creation form has enough variation in its UI that automated form-filling is unreliable. Flagged for manual review.

SMS notifications

Twilio is not yet wired. Notification tests verify in-app display only. Expected to fail SMS checks — this is known and documented in the UAT test plans.

Photo upload on walk completion

File input interactions are not tested. The completion note is tested; the photo field is skipped.
